# AssettoServer Race Control

Race Control is the native Windows event editor and launcher for this fork's LAN race bots. It reads cars, skins, tracks, layouts, weather, previews, pit capacity, AI lines, checksum data, and collision inputs from the local Assetto Corsa installation. It never edits installed game content.

The installed-content catalog is cached per Assetto Corsa installation under `%LocalAppData%\AssettoServer Race Control\Cache`. After the first scan, startup loads that cache immediately and checks for added, removed, or changed cars and track layouts in the background. The refreshed catalog replaces the cache atomically and preserves any grid edits made while scanning. Use **Refresh content** to force an immediate foreground rescan.

The application targets .NET 10 WPF and opens in Visual Studio 2026 through `AssettoServer.slnx`. Its three projects are:

- `AssettoServer.RaceControl`: native WPF interface;
- `AssettoServer.RaceControl.Core`: content, validation, configuration, staging, persistence, and process services;
- `AssettoServer.RaceControl.Tests`: focused NUnit regressions.

## Workflow

1. Race Control detects the standard Steam installation and bundled standalone server. To use different locations, open the cog menu and select **Local Installations**.
2. Choose a track layout. The UI reports its pit capacity and whether a usable `fast_lane.ai` exists.
3. Build the **Grid**. Every entry can select any installed car and skin. `Auto` means a bot occupies the slot until a human claims it, `Fixed` is bot-only, `None` is a human-only racing slot, and `Spectator` reserves a camera-only connection. New and default entries are `Auto`.
4. Set sessions, rules, weather, bots, rigid-body fidelity, and LAN ports. Clear **Enable server-authoritative race bots** to stage every entry as human-only without losing the saved per-slot modes.
5. Open **Launch & Live**, validate, then use **Start new**. Content Manager clients discover the event under `Drive -> Online -> LAN`.

**Race Bots -> Player slot selection** controls which eligible `Auto` slot is claimed when several slots use the connecting player's selected car. **First** uses the lowest configured grid entry, **Last** uses the highest, and **Random** chooses independently on every connection. Occupied, fixed-bot, human-only, and otherwise ineligible slots are skipped; explicit GUID reservations and CSP slot requests retain priority. Before race start this controls grid placement. With mid-race bot takeover enabled, it instead selects the active bot to replace at its current track position.

**Grid -> Populate by characteristics** builds a requested number of `Auto` racing entries from installed, bot-capable cars. Filters support exact `ui_car.json` class, maximum horsepower, exact model year, maximum horsepower per tonne, or the complete eligible catalog. Cars without metadata required by the selected filter are excluded rather than guessed. When fewer slots than cars match, Race Control samples across the sorted catalog instead of taking only the first names; larger grids cycle matching models and their installed skins. Population replaces racing rows but retains configured spectator reservations. Protocol capacity is enforced immediately, while a grid larger than the selected layout's pit capacity remains visible and is trimmed from the end during staging as usual.

**Grid -> Favorite grids** saves and reloads the grid independently from the event preset. A favorite includes car, skin, driver and team names, slot modes, ballast, restrictor, nation, and spectator rows; loading one does not change the track, sessions, conditions, bot settings, or network configuration. Favorites are stored under `%LocalAppData%\AssettoServer Race Control\Grids`. Saving with an existing name updates that favorite.

**Race Bots -> Racecraft** uses 0..1 sliders for the field's baseline **Skill** and **Aggression**. Their 0..100% variance sliders generate stable per-slot values above and below each baseline, so a grid remains mixed but reproducible across restarts and accelerated simulations. Variance is relative to the baseline and values are clamped to 0..1. The Grid's optional **Skill** and **Aggression** cells override the generated value for that specific car slot; leave a cell blank to keep automatic variance. Per-slot racecraft is retained by event presets, favorite grids, and Race Control Content Manager exports. Skill affects pace and corner-speed planning, while aggression affects passing distance, commitment, extension, yielding, and gap acceptance.

`Spectator` entries are appended after the racing roster when the server configuration is rendered. They count toward Assetto Corsa's 254-client protocol limit and must name an installed carrier car, but they do not consume pit boxes, physical grid poses, rigid-body bot geometry, race positions, lap packets, or race-completion responsibility. A spectator client must advertise CSP's `SPECTATING_AWARE` feature; exact CSP slot requests can claim a spectator entry even while the race session is closed to new drivers. Unmodified clients cannot claim these slots.

Race Control keeps one reusable runnable server rather than copying the self-contained payload for every start. Staging replaces `Instances\Current` only after preserving the previous run's compact configuration, logs, telemetry summary/events, track map, and gzip-compressed telemetry samples under `History`. Use **Export package…** when a complete portable server ZIP is actually needed; export is available while the server is stopped and does not disturb the working instance.

## FPS Deathmatch

Current runtime corrections are deliberately presentation- and movement-layer specific. Modern
crouch and prone apply an exact -0.50 m world-up offset to the animated KN5 child because CSP's
KN5-to-KSANIM conversion raises those hips tracks by 50 cm; the authoritative actor root and hitbox
do not move. Grounded movement uses graduated 0.48 m, 0.8 m, and 1.2 m probes to bridge an
imported collision-only floor strip only when comparable reachable support exists on two opposing
sides. That rule covers Nuketown's measured 0.45-0.50 m colored-ring hole and the 1.05 m side-yard
collision void around `(17.31, -0.07, 10.69)`, while one-sided ledges, wider gaps, and walls remain
blocking. Overlapping imported floor bands can report several visually equivalent support planes;
changes up to 0.22 m now converge at no more than 0.025 m per 0.08 m sweep instead of making the
authoritative capsule pop between them. None of these corrections requires re-preparing an existing
version-4 FPS arena.

**Event mode** switches between the existing Racing editor and an isolated **FPS** editor. Each mode retains its unsaved draft while the application is open and has a separately filtered saved-preset list. FPS mode renames the circuit selector to Map / Arena and layout, replaces sessions with Deathmatch settings, exposes FPS-specific difficulty, aggression, variance, and 50–200 HP controls, and displays grid roles as `Auto`, `Bot`, `Human`, and `Spectator`. Racing presets and behavior are not migrated or rewritten when modes are switched.

FPS mode is an experimental solo-deathmatch milestone, not a completed shooter release. Choose a map, use **Prepare as FPS arena**, and stage a two-or-more-slot event. Preparation version 4 reads physical collision, explicit collision-proxy KN5s, and selectively named solid visual meshes (including Fire Pit's `FPV_` structural meshes) together with `AC_START_n` transforms. It also builds a layered 0.6 m navigation asset with standing-capsule clearance, walkable slopes, stairs, and explicit drop, jump, vault, and mantle links. Redundant jump/traversal links across ordinary walkable neighbors are omitted so large arenas do not inflate the runtime search graph. **Bounds padding** controls the horizontal area sampled beyond the outermost spawn (5–100 m, default 45 m); compact arenas can use a smaller value, but changing it requires preparing the arena again. Optional include/exclude glob lists are retained in the AppData arena sidecar for track-specific corrections; foliage, decals, billboards, glass, and effects remain excluded by default. Preparation writes bounded spawns plus navigation and collision-BVH summaries to `%LocalAppData%\AssettoServer Race Control\FpsArenas` and atomically stores the generated geometry and navigation binaries in `Cache\Physics`; the first staging pass reuses those binaries unless a track model, bounds padding, collision override, or preparation version has changed. The BVH itself is rebuilt deterministically in memory when a staged server loads the binary geometry, so existing preparation-version-4 arenas receive the runtime optimization without being rejected. Runtime capsule validation treats every walkable top within the 48 cm auto-step range as support rather than a ceiling, even during the one-tick support-height reconciliation at thin imported paint, kerb, and terrain layers. Unrelated server rebuilds do not invalidate prepared FPS assets. It never modifies the installed track. Older sidecars must be prepared again. **Show FPS arenas only** filters against current sidecars. **Export FPS Client Pack** version 26 writes the CSP version, carrier-car requirement, both visual themes, project-owned assets, attributed third-party assets, audio, and the optional hybrid HUD app; the authoritative online Lua client is still delivered by AssettoServer. The confirmed CSP rendering pipeline and failure checklist are maintained in [FPS client rendering handoff](fps-client-rendering.md), and the generated skinned-model pipeline is maintained in [FPS Modern visual theme handoff](fps-modern-theme.md).

**Lobby Setup -> Theme** selects one server-wide FPS presentation. **Blocks** is the unchanged default. **Modern** loads the generated animated army officer, attached third-person carbine, and animated first-person arms/carbine. The selection is captured when the server is staged and is shown read-only in Live Match and the web GUI; editing the preset during a running match takes effect only after staging/restarting. Movement, collision, hitboxes, hitscan, damage, ammunition, and networking are theme-independent. Any Modern asset or animation failure reports a persistent error and immediately rebuilds the playable Blocks presentation. Dynamic skinned KN5 loading still has an explicit CSP `0.3.0-preview520` live acceptance gate documented in the Modern handoff.

**Deathmatch -> Loadouts** configures server allow-lists plus separate human and bot defaults for one main weapon, one lethal, and one secondary weapon. The initial catalog contains Assault Rifle or Compact SMG, Frag or Sticky Grenade, and Desert Eagle or Colt 1911. A joining human claims the carrier slot but remains inactive until the server accepts an explicit loadout confirmation; a locally saved choice is preselected but never auto-spawns the player. Changes made from the FPS pause menu are validated immediately and queued until that actor's next respawn. Auto slots return to the bot default when their human disconnects. Main and secondary ammunition are independent, `1`/`2` switches slots with a 0.35 s action lock and cancels reload, and `G` throws the one lethal granted per life. Frag grenades bounce and use a 3 s fuse; sticky grenades attach to actors or world collision and use a 2.2 s fuse. Both use server-side motion, line-of-sight radial damage, self-damage, and reliable item-attributed hit/kill results. Grenades survive their owner's death, detach from a dead or respawned target, and are removed if the owner disconnects. The Desert Eagle uses ELIZION's attributed CC BY model and the Colt 1911 uses DanaeH's attributed CC BY model for first person, third person, and dropped pickups in both themes. Compact SMG, both grenades, and item-specific audio remain placeholders. Client pack 28 and base asset archive v19 carry both real pistols, two-arm first-person KN5s, five animation tracks per pistol, separately animated magazines, and attribution notices. The firing hand remains unchanged in hip-fire and ADS; reload tilts the complete pistol rig down while the support hand rises from below to follow the magazine, then returns fully off-screen. Dedicated pistol hip/ADS offsets keep the sights aligned without inheriting the rifle's near-camera parallax. The HUD and loadout model share one CSP remote-assets request for that archive so cache extraction cannot race.

The match runs over one long AC Practice session. Every participant occupies a normal AC carrier slot, while the embedded CSP online script immobilizes and hides carrier cars, owns the camera, captures keyboard/mouse or Xbox-controller input, renders a project-owned procedural operator, and draws the crosshair, health, clock, kill feed, scoreboard, and final ranking. Remote operators and the first-person rifle are dynamic CSP scene nodes created in the early guaranteed portion of the simulation-update phase. Remote world nodes are created, interpolated, and transformed atomically per actor in that early update callback so CSP cannot complete preparation while skipping movement, while the camera-relative rifle is transformed in `frameBegin` to remain synchronized with the view; both retain normal depth, per-frame motion history, and floating-origin-corrected transforms; short-lived tracers and impacts remain custom effect draws. `Auto` and `Bot` slots are active authoritative opponents: they acquire enemies in the same reachable navigation component, path at 5 Hz, steer and collide at 60 Hz, traverse prepared links, search last-known positions, strafe, fire, reload, take damage, die, and choose safer respawns. A blocked combat strafe immediately falls back to the reachable path instead of alternating in place. A failed mantle or vault edge is quarantined for three seconds and excluded from replanning so an invalid authored link cannot consume every 60 Hz tick. Difficulty controls reaction, tracking, accuracy, and burst length; its low end deliberately uses slow reacquisition, wide aim error, short bursts, and long pauses. Aggression controls engagement distance, pursuit memory, strafing, exposure, and target switching. After repeated failed replans a stuck bot is recovered to a safe spawn without changing its score. Bots use the same movement resolver and server-validated rifle path as human actors. Their shot follows the tracked actor yaw and pitch rather than silently snapping to the target, and world occlusion is checked against the exact entry point of the target capsule. The server asset archive includes a generated 4-by-4 operator UV atlas; explicit mesh UV regions map the face and hair, shirt and sleeves, cargo trousers, straps, gloves, and boots instead of stretching a material swatch over the whole body. The rifle holds 40 rounds and starts with four reserve magazines; `R` begins a timed manual reload and an empty magazine reloads automatically. Authoritative hitscan and the visible tracer originate at the stance-adjusted center of view; the displaced weapon muzzle is cosmetic only. Targets use their full standing, crouching, or prone capsule rather than a waist-height sphere. Every accepted server shot is broadcast to every client and produces a small short-lived tracer and muzzle flash plus a pooled shadowless warm point light for 55 ms. Local first-person fire retains its 5.5 m illumination range; local third-person and remote fire use a 2.25 m illumination range around each actor's interpolated rendered weapon pose and stance height. Remote flares use three distance LODs and a 500 m light fade threshold, so the visible flash is not culled or reduced below a few pixels across the arena even though its physical illumination stays local. World hits leave a temporary impact mark with spark fragments and smoke. The dynamic light is disposed after a one-second reuse window and safely disables itself if the client CSP build cannot create it. Actor impact marks are tied to the victim's spawn generation and are discarded on death or respawn. Press `F6` to switch between first-person and a collision-clipped over-the-shoulder view. The authoritative capsule walks slopes up to 45 degrees and auto-steps stair, kerb, terrain-seam, and decorative ridge faces up to the shared 0.48 m limit, including imported faces without an exact matching tread. Projected edge cracks up to 0.06 m snap to nearby walkable support; missing imported floor strips up to 1.2 m are bridged through graduated probes only while comparable support exists on opposing sides. Wider gaps and true ledges still enter a gravity-driven fall; taller geometry remains solid and requires a walkable step top, jumping, vaulting, or mantling. Movement uses bounded capsule sweeps with contact-normal sliding and a visual wall-clearance skin. All ground, capsule, step-top, and hitscan lookups use one deterministic three-dimensional static BVH with at most eight source triangles per leaf; the former fixed 4 m buckets and their multi-thousand-triangle worst cells no longer exist. Grounded and airborne depenetration are capped at 64 distributed probes before the existing safe-pose rollback takes over, bounding a malformed or impossible collision recovery within one simulation tick. Grounded poses are retained as rollback points; an airborne capsule which overlaps the side of a ledge is pushed to the nearest horizontal clearance and continues falling instead of looping at its last mid-air height. Airborne sweeps do not require a walkable support directly beneath every intermediate sample, so narrow imported terrain cracks cannot masquerade as walls and freeze a jump; while unsupported, the last authoritative support height remains stable instead of recursively becoming a new lower ground plane. Grounded edge traversal still requires support, so this does not permit walking over true ledges. Vault and mantle paths are collision-preflighted and checked every simulation tick; the capsule lifts beside a closed obstacle, crosses only above it, and then lowers instead of diagonally cutting through enclosed crates. Blocked directions are included in authoritative snapshots: client prediction removes only motion into the surface, keeps tangent and escape movement, and reconciles through the same multi-height collision fan instead of freezing at the 20 Hz snapshot rate. The first-person rifle retracts smoothly near scenery. A tap always remains a normal jump; mantling begins only after holding jump for 0.2 seconds near a valid ledge. The server runs a separate fixed-step `FpsWorld`: inputs are authenticated to the sender's assigned slot, stale or impossible inputs are rejected, actor snapshots (including spawn generation, landing surface, collision constraint, ammunition, and reload state) are sent at 20 Hz, local and remote poses are reconciled immediately after respawn, firing and damage are server-authoritative, and reliable events carry hits, kills, score, and match state. Once per second server logs now include authoritative bot pose, mode, target, path progress, blocked state, and movement delta. The tick-cost diagnostic records the maximum tick's human, bot, post-processing, and path-planning time together with BVH query, candidate, maximum-query, and depenetration counts, so future regressions can be assigned to a phase instead of inferred from total backlog. The client diagnostic packet reports one remote actor's snapshot and rendered pose so a visible/server hitbox mismatch can be measured directly. No client-reported hit is accepted and no `acs.exe` hook is installed.

Client pack version 26 includes one background-loaded **ASRC FPS HUD** app. A versioned local `ac.connect` bridge exposes presentation state only; the app uses CSP's exclusive-HUD callback to replace normal AC UI and other Lua/Python apps during active FPS gameplay, then yields in pre-match menus, results, replay, and non-FPS sessions. The server-delivered online script owns the FPS pause surface: it replaces AC/CSP's racing-oriented pause screen with a **MATCH MENU**, live standings, **RETURN TO MATCH**, **FPS CONTROLS**, **LOADOUT**, **TIME & WEATHER**, **ASSETTO CORSA OPTIONS**, and a confirmed **LEAVE SERVER** action. CSP does not invoke an online server script's normal `script.drawUI()` pass in this setup, so the exclusive-HUD callback owns both rendering and input. Pause buttons and submenus therefore use project-owned screen-space drawing and hit rectangles instead of CSP controls that render empty or lose input on this surface. The controls submenu captures keyboard and mouse buttons directly and persists fire, sprint, crouch/prone, reload, jump, grenade, and melee bindings with `ac.storage`; grenade is active and melee remains reserved. The crouch row also persists **HOLD** or **TOGGLE** behavior. In toggle mode, a short press latches crouch, a second short press stands, and holding the same control still enters prone. It also persists independent **HIP-FIRE AIM SENSITIVITY** and **ADS AIM SENSITIVITY** sliders for both mouse and right-stick look. Defaults preserve the existing hip-fire response at 100% and set ADS to 80%; changing one slider does not overwrite the other. Rebinding replaces the previous keyboard input, while the existing controller path remains independent. **TIME & WEATHER** no longer attempts to open Pure Planner, whose controller is unavailable during an online session. It sends the selected hour and WeatherFX type to the authoritative server, which broadcasts the resulting time and weather state to every CSP/Pure client. The lowest connected non-spectator session owns this in-game control until user roles are introduced. AC options can still yield to the full native menu for video, audio, controls, and CSP settings. Pause ownership is cleared from the always-running simulation state transition after resuming, because the companion HUD can legitimately pre-empt the online exclusive callback's first gameplay frame. If the app heartbeat is missing, stale for 0.5 seconds, or version-incompatible, the embedded online script immediately resumes the complete gameplay HUD, including the same 40 m player-up combat radar. Opponents appear only while track geometry has line of sight or for two seconds after an authoritative shot. Version 26 retains the corrected radar handedness, decoded player names, authoritative score presentation, both FPS themes, and delivers the Modern rifle through the same skinned render path as its arms. Its redesigned lower-left operator panel shows configured health and server-backed stamina, while the lower-right weapon panel uses a transparent render of the shipped carbine with rounds, reserve magazines, and reload progress; the online fallback draws the same information and artwork. Modern asset archive revision 8 changes the remote URL whenever KN5 or KSANIM content changes so CSP cannot silently reuse stale character poses. The Modern operator uses a baked two-bone rifle-ready grip instead of the source T-pose; its generated crouch and prone clips own skeleton-space grounding while the KN5 child remains at its authored scene origin. Prone uses immediate local stance plus redundant protocol-v2 snapshot state so local and remote third-person models select the authored horizontal pose reliably. Jump from crouch immediately stands and performs the jump, remaining standing until crouch is released; jump from prone is consumed as a prone-to-crouch transition. Its optic lens is a separately skinned, alpha-blended mesh using a compact generated red-dot texture, and HUD bridge v5 suppresses the ordinary crosshair during ADS while retaining hitmarkers. A kill is 100 points; every other attacker who damaged that victim during the same life receives one 50-point assist. The reliable award event carries total score and server-classified kill flags so both HUD paths show the same fading crosshair-adjacent `KILL`, `ASSIST`, `HEADSHOT`, and `ONE SHOT` messages. Match placement and the configured win limit remain kill-based. Content Manager presets, desktops, and user app configuration are not modified.

Sprint consumes a server-authoritative 100-point stamina pool only while a standing, grounded actor is actually moving. Continuous sprint lasts about five seconds, recovery begins after a 0.9-second delay, and exhaustion remains latched until 25 stamina so latency cannot oscillate sprint speed. Health regeneration is also server-authoritative: every accepted hit restarts a 3.5-second out-of-combat delay, after which health recovers at 15 HP/s up to the configured maximum, slightly slower than the 18 stamina/s recovery rate. Death, respawn, and a newly claimed player slot clear partial regeneration state. The existing vitality snapshot carries both values, so no protocol or client-pack change is required. The online client predicts stamina and reconciles both values from that packed snapshot.

Hold right mouse or the controller left trigger to aim down sights. ADS smoothly aligns the optic to screen center, narrows the FPS camera field of view, suppresses weapon bob and visual kick, reduces camera recoil, tightens authoritative sustained-fire spread, cancels sprint, and reduces authoritative movement speed by 60% once fully aimed. Standing fire now has a small 1.10 spread and 1.08 visual/camera-recoil multiplier; crouching reduces those multipliers to 0.70, and prone reduces them to 0.55. The stance multiplier composes with ADS, so crouched ADS is more stable and accurate than standing ADS without changing damage or fire rate. Client prediction applies the same 40% movement multiplier, so the slower movement does not introduce reconciliation rubber-banding. The FPS-only camera uses a minimum stable 0.1 mm near plane—effectively the camera surface—so the close Modern receiver and stock continue behind the view instead of exposing sliced geometry; racing cameras are not changed. At steep downward look angles, a cubic pull-in curve moves only the Modern viewmodel toward that camera surface, hiding the finite arm and stock ends without changing aim or shot origin. Viewmodel orientation uses a complete camera-relative orthonormal frame, including at steep up/down pitch, so ADS no longer shears or folds the rifle. On death, the authored limb collapse is combined with an 84-degree foot-pivot, inherited momentum, gravity, and damped settling; the corpse is hidden after 3.75 seconds or on respawn. The carried rifle detaches into a separate authoritative pickup. A different living player carrying the same rifle can collect it after 0.4 seconds for exactly one reserve magazine, up to four reserves; uncollected drops expire after 15 seconds. Gameplay state and hitboxes remain authoritative and no unsafe dynamic skinned ragdoll is created. Shot origin, damage, and collision remain server-authoritative. FPS gamepad input is decoded independently from racing controls: left-stick movement and right-stick horizontal look use FPS-correct handedness, the left trigger aims, the right trigger fires, Xbox `Y` switches between the primary and secondary weapon slots, and `RB` throws the equipped lethal grenade. AC throttle/brake are explicitly suppressed while FPS owns input. This logic is delivered only with FPS mode; racing controller behavior and bindings are unchanged.

Before the first **Drive**, the normal AC pre-match controls remain available, but the FPS script replaces the out-of-bounds carrier-pit background with a fixed, collision-clipped establishing camera anchored at the player's authoritative arena spawn. After gameplay has begun, pause, results, and replay return camera ownership to AC as before.

During FPS sessions, **Live Match** reads authoritative actors directly from `FpsWorld` instead of the hidden carrier cars used to host AC connections. Its top-down view draws the prepared navigation cells as the arena floor and overlays current player and bot positions, headings, names, health, kills, and deaths. The desktop **Arena view**, **Selected player**, and **Environment** cards are collapsible. The web Live Match surface provides the same collapsible arena, selected-player, and environment panels. Environment changes from either launcher use the same authoritative WeatherFX path as the pause menu, so connected Pure clients remain synchronized. Racing sessions continue to use their existing spline and car-telemetry map without behavior changes.

The next compatibility gate is two real LAN clients plus bots completing five consecutive kill/respawn cycles with stable camera ownership and identical scores. Auto-slot transfer, disconnect replacement, production animation and audio, broader arena tooling, and additional-map tuning follow that gate. No native executable hook is planned.

If more entries are requested than the track has pit boxes, validation shows a warning and staging keeps the first entries that fit. This is not a launch blocker.

**Event & Content -> Conditions -> Time of day** selects the starting hour from `00:00` through `23:00`. Race Control converts that clock value to Assetto Corsa's native `SUN_ANGLE` representation when staging or exporting a Content Manager preset, and converts imported `SUN_ANGLE` values back to the nearest displayed hour. Existing presets that store only a sun angle remain compatible.

While the `F6` third-person camera is active, hold either `Shift` key and scroll the mouse wheel to move the camera smoothly between 1.25 m and 7 m. Scrolling up zooms in and scrolling down zooms out. This binding exists only in the server-delivered FPS client and does not alter racing controls.

Grounded movement also handles one malformed-import case which ordinary stepping cannot: a thin decorative support can end before the real floor resumes. The capsule may cross at most 0.65 m of unsupported collision only when a forward probe confirms a real walkable landing. An arena edge with no landing remains impassable, and wall collision is still evaluated throughout the sweep.

Firearm damage uses a server-authoritative effective-range profile evaluated at the measured hit distance. Assault Rifle damage is 34 through 20 m, 24 from above 20 m through 45 m, and 17 beyond 45 m. The placeholder Compact SMG currently inherits those range breakpoints with 25/18/13 damage. Both pistols use 8 m and 15 m breakpoints: the Desert Eagle deals 55/39/28 damage and the Colt 1911 deals 34/24/17 damage. The medium and minimum bands are 70% and 50% of each weapon's maximum damage, rounded to the nearest whole health point.

## Menus and settings

The native menu bar groups event actions under **File**, appearance under **View**, process actions under **Server**, and documentation under **Help**. The cog button in the header and `Ctrl+,` both open application settings. `Ctrl+N` creates a new race and `Ctrl+S` saves the current preset.

**View -> Theme** switches between System, Light, and Dark immediately. System resolves the current Windows application theme when Race Control starts. The selected palette covers the window chrome, navigation, page backgrounds, cards, inputs, menus, grids, popups, console, and native title bars.

The Settings window separates **General** preferences, **Local Installations**, and the **Web GUI** listener. General controls compact grid rows, loading the most recent saved race at startup, returning to the last open page, and confirmation before an active server is stopped on exit. Local Installations selects the Assetto Corsa content root and standalone AssettoServer payload. These machine-specific paths take precedence over paths embedded in older race presets, so loading an event cannot silently switch the app to another installation. All application-wide preferences are saved in `%LocalAppData%\AssettoServer Race Control\settings.json`.

## Web GUI

Race Control starts a browser dashboard automatically with the desktop launcher. The safe defaults are **enabled**, bind address `127.0.0.1`, and port `8772`; use the header's **WEB GUI** button or **View -> Open Web GUI** to open it. The Web GUI port is independent of AssettoServer's game TCP/UDP and HTTP ports. Saving changed Web GUI settings restarts only this listener.

Closing the main Race Control window owns the desktop process lifetime. The close path first cancels
in-flight dashboard requests and asynchronously stops Kestrel before WPF exits; it never blocks the
UI dispatcher waiting for a request which is itself waiting on that dispatcher. This prevents the
headless `AssettoServer Race Control.exe` process and port `8772` listener from surviving the window.

The first web release is a local-owner control surface. It provides launcher and server state, responsive desktop/mobile views, the authoritative live race or match map, real participant names and results, and guarded server/session start, stop, and restart actions. Preset authoring remains in the desktop launcher. The browser reads the same `state.json` and `track.json` files used by the desktop Live view; it does not infer positions from carrier cars or client visuals.

The listener accepts only loopback or a specific RFC1918 private IPv4 address. It never binds to `0.0.0.0` or a public address, publishes no saved game/admin passwords, sends no permissive CORS headers, denies framing, and requires a random per-process control token on state-changing requests. Binding to a LAN address still grants local-owner control to every device that can reach the port because login and authorization do not exist yet. Keep the loopback default unless that exposure is intentional.

The versioned routes are `/api/v1/health`, `/api/v1/status`, `/api/v1/track`, and `/api/v1/actions/{action}`. The API prefix and presentation/control split are reserved for the planned second stage: user profiles, authenticated sessions, `admin` and `user` roles, and role-appropriate Content Manager join links. That future work must add authentication before making LAN binding the default.

## Live Race view

`LIVE RACE` provides a server-authoritative top-down view of every active bot and connected human. Click a car marker or use the car list to select it, then clear **Full track view** to follow it. Adjust the follow-view width with its slider or the mouse wheel. Scrolling inward from the full-track camera enters the selected-car view; scrolling outward past the maximum returns to fit-to-track.

Selecting an active server bot opens a compact control panel in the map's upper-right corner:

- **STOP** removes its horizontal and angular velocity every physics tick, stopping it at its current location; the button becomes green **GO**, which returns the bot to autonomous AI.
- **TELEPORT P1** relocates it about 12 metres ahead of the current physical leader on the racing spline. Teleported distance is not added to its lap tracker, so this does not award a skipped lap.
- **TAKE OVER** switches the map to a Direct3D 11 chase view and routes arrow-key or Xbox-controller input to that bot's existing rigid-body controller. Left/right or the left stick steer, Up or the right trigger accelerates, and Down/Space or the left trigger brakes. A compact HUD shows authoritative speed, protocol gear, and engine RPM. **RELEASE CONTROL** or Escape returns it to AI. While takeover is active, input, authoritative snapshots, UI polling, and rendering target 60 Hz; normal live-map monitoring retains its lower-overhead rates.

Manual input is local-only, bounded, and fails safe: if fresh input stops arriving for 750 ms, throttle is removed and full braking is applied. Takeover controls only server-owned bots; unmodified Assetto Corsa human clients remain authoritative for their own cars. The 2.5D view is a Race Control visualization of server telemetry, not the Assetto Corsa renderer.

The controls deliberately distinguish the process from the session:

- **Start live server**, **Stop server**, and **Restart server** manage the AssettoServer process.
- **Start race** selects the configured race and begins its normal grid countdown even with zero humans.
- **Stop race** broadcasts race-over, classifies unfinished participants as DNF, holds the bots, and leaves the server online.
- **Restart race** rebuilds the race state and starts a fresh countdown regardless of connected-player count.
- **Simulate race** stages the current setup and runs its bots with deterministic virtual time and no network listeners. Seed and duration are set beside the button. **Limit by** selects virtual minutes or leader laps; in Laps mode the run stops when the leading active car reaches the selected count, while normal configured race completion can still end it earlier. The **Time acceleration** slider sets a 1x-100x target and remains live while the simulation runs. A change is sent through the same local-only command channel and rebases the pacing clock, so large adjustments do not cause a catch-up burst or a long stall. Simulation remains fixed-step and can run slower than the target when the CPU cannot keep up.

The progress bar advances toward the first condition that can end the run: configured race completion, the selected leader-lap limit, or the maximum virtual-time limit. Fractional leader position provides continuous progress in Laps mode. Its remaining wall-time estimate uses the current acceleration target and is therefore approximate; a race can finish sooner than its selected maximum.

When a simulation completes, reaches its limit, or is stopped, the map is covered by its final race classification even if the server has already transitioned to practice. The table shows rank, driver and car, laps, total and best-lap time, average and top speed, contact episodes, full-stop count and stopped duration, and completed/DNF status. The summary keeps contact manifolds and server recoveries as separate fields. Accepted STOP/GO commands remain deliberate stopped-obstacle test episodes; the overview reports completed versus committed passes instead of discarding those commands as artificial data. Starting-grid time is excluded from full stops. **Back to map** dismisses the panel without discarding the result.

**Take over** replaces the flat chase approximation with a Vortice-backed Direct3D 11 scene hosted in WPF. Separate static-track and dynamic-car GPU buffers render a lit road ribbon, green terrain extending beyond the server's off-course recovery envelope, and vehicle geometry; the perspective camera, road elevation, vehicle transforms, gear, and engine RPM use authoritative AI telemetry streamed by the server. The current renderer uses deliberately simple vehicle geometry rather than pretending to load Kunos materials or meshes; this keeps simulation authority and visual asset loading separate while providing correct spatial motion, slopes, occlusion, and mouse-wheel chase distance. Gravel and other material-specific runoff require track-surface metadata that is not currently part of live telemetry and are therefore not guessed from spline geometry.

Takeover remains subject to the prepared physical track. If manual steering leaves all drivable geometry, the authoritative physics world immediately resets the car to a supported course position. A missing surface is never treated as a valid continuation at the falling body's current height.

Live control remains independent of AssettoServer's LAN HTTP port. Race Control passes a private directory inside the staged instance; AssettoServer writes `state.json` and `track.json` there and consumes single-use command files from `commands`. The optional Race Control Web GUI is a separate launcher-owned listener with its own bind address, port, and local-owner safety boundary described above.

The working instance directory is deliberately reused between launches. The live viewer therefore keys its track cache by both launch generation and the `track.json` file revision, and ignores empty or partial maps until a renderable replacement appears. Switching event mode, staging, launching, or restarting invalidates the cached map so both the top-down and takeover views rebuild from the current event.

## Content Manager interoperation

**Import latest CM preset** reads the most recently modified `server_cfg.ini` and `entry_list.ini` pair under `<Assetto Corsa>\server\presets`. A single imported entry is cloned to the two-slot minimum. Import does not modify the CM preset.

**Export new CM preset** writes a new `RACE_CONTROL_*` directory and never overwrites an existing CM preset. The native app is the authoritative editor for bot-specific options because ordinary CM presets do not model the race-bot extension.

## Files and safety

Mutable application data lives under `%LocalAppData%\AssettoServer Race Control`:

- `Presets`: JSON event presets;
- `Grids`: reusable named grid favorites;
- `FpsArenas`: FPS arena bounds and safe-spawn sidecars, separate from installed tracks;
- `FpsClientPacks`: reserved for exported companion content after the compatibility gate;
- `Instances\Current`: the single reusable runnable server;
- `History`: compact per-run configuration, logs, results, and compressed telemetry rather than duplicated server binaries and physics assets;
- `Cache\Physics`: prepared track/grid/car collision assets keyed by input and server versions;
- `Logs`: reserved for exported logs.

The current working instance contains the published server, generated configuration, required `data.acd` checksum sources, the selected `fast_lane.ai`, and a compressed prepared physics asset. Compact history deliberately omits the server payload, copied checksum content, and `race-physics.bin`; simulation `samples.jsonl` is retained as `samples.jsonl.gz`. Passwords are present in the locally retained generated `server_cfg.ini`, as they are in CM presets, but are excluded from the instance manifest and UI logs.

This storage model applies to newly staged runs. Legacy timestamped instance directories created by older builds are left untouched so an update never deletes user data implicitly; they can be reviewed or removed separately after confirming they are no longer needed.

V1 accepts only loopback or RFC1918 IPv4 listeners. Lobby registration, Steam authentication, UPnP, and automatic port forwarding are forced off. Stopping from the GUI creates a per-instance control file; the server observes it and shuts its host down gracefully. A process-tree termination is used only if graceful shutdown exceeds ten seconds.

## Build and publish

From a PowerShell prompt in the repository:

```powershell
dotnet test .\AssettoServer.RaceControl.Tests\AssettoServer.RaceControl.Tests.csproj -c Release
.\tools\Publish-RaceControl.ps1
```

The portable self-contained output is always replaced at `out-race-control`; publishing does not create architecture- or change-specific output folders. The root contains the single-file Race Control executable and notices, runtime/server files live under `lib`, framework localization resources live under `lang`, and documentation lives under `docs`. Source and build instructions must accompany any distributed or network-accessible modified AGPL build.

For a local installed-content smoke test using two bots at Magione:

```powershell
.\tools\Test-RaceControlLocal.ps1
```

The smoke test scans the installed catalog, stages an isolated two-slot instance, prepares its rigid-body inputs, starts it on loopback-only acceptance ports, requests graceful shutdown, and retains the logs under `.artifacts\race-control-local-acceptance`.

For repeated bot-only regression races across installed tracks, use:

```powershell
.\tools\Test-RaceBotsMatrix.ps1 -Slots 8 -Seeds 1,2,3
```

The runner uses the bundled server's network-free virtual-time mode, preserves structured per-run telemetry, and writes an aggregate report under `.artifacts\race-bot-matrix`. It never edits installed Assetto Corsa content. The local acceptance runner also supports `-SimulateRace -SimulationTimeScale 10` to verify paced live telemetry and the versioned per-car result fields. Add `-VerifyStoppedObstaclePassing` to stop the settled race leader and require another bot to steer around it, complete the pass, and gain race position before the test can pass.

Use `-AllUsableTracks -FullGrid -Seeds 1 -ContinueOnError` for an installation-wide diagnostic sweep. The runner records preflight-incompatible layouts separately and does not let one failed track abort later runs.

## Current limits

- Race Control is a portable build, not yet an MSIX/MSI installer.
- Installed mod metadata can be incomplete. Such content remains visible, but validation blocks missing server checksums, AI lines, models, or bot colliders required by the selected mode.
- The cached background scan preflights race-bot spline closure/readability and physical `MODEL_*` references. Unsupported content is rejected before a server preparation process starts.
- Track UI metadata can overstate pit capacity. After physics preparation, Race Control reads the actual contiguous `AC_START_n` count and drops trailing staged entries rather than advertising invalid slots.
- The server derives bounded vehicle-controller values from `ui_car.json`; exact collision geometry does not turn the server into Kunos' proprietary tyre, suspension, aero, or damage simulation.
- Public hosting, automatic firewall rule changes, port forwarding, remote spectator administration, and remote server management are intentionally out of scope for this LAN release.
